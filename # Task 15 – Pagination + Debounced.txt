# Task 15 – Pagination + Debounced Search



## 1. What are LIMIT and OFFSET in SQL?

`LIMIT` is used to specify how many records should be returned from the database.

`OFFSET` specifies how many records should be skipped before returning the results.

For example:

```sql
SELECT * FROM products
LIMIT 8 OFFSET 16;
```

This returns 8 products after skipping the first 16 products.

### Page 3 with 8 products per page

Formula:

```text
LIMIT = products per page
OFFSET = (current page - 1) × products per page
```

Given:

```text
Total products = 47
Products per page = 8
Current page = 3
```

Therefore:

```text
LIMIT = 8

OFFSET = (3 - 1) × 8
       = 16
```

So the exact values are:

**LIMIT = 8**
**OFFSET = 16**

Page 3 will display products **17 to 24**.

## 2. How does useDebounce work?

`useDebounce` is a custom React hook used to delay updating a value until the user stops changing it for a specific amount of time.

In the search feature, this is useful because the API does not need to be called every time the user types a letter.

For example, if the user types:

```text
wireless mouse
```

the API should not be called separately for:

```text
w
wi
wir
wire
wirel
...
```

Instead, the hook waits for the debounce delay, such as 300 milliseconds, after the user stops typing and then allows the search API request to happen.

A typical implementation is:

```js
function useDebounce(value, delay) {
    const [debouncedValue, setDebouncedValue] = useState(value);

    useEffect(() => {
        const timer = setTimeout(() => {
            setDebouncedValue(value);
        }, delay);

        return () => clearTimeout(timer);
    }, [value, delay]);

    return debouncedValue;
}
```

### What does the cleanup function do?

```js
return () => clearTimeout(timer);
```

This cancels the previous timer when the value changes before the delay finishes.

For example, if the user types another letter within 300 milliseconds, the old timer is cancelled and a new timer starts.

This is important because it prevents unnecessary updates and API calls for every keystroke. It makes the search feature faster and reduces unnecessary requests to the backend.

## 3. Why do we reset currentPage to 1 when the search term changes?

When the user changes the search term, the result set also changes.

For example, suppose the user is on:

```text
Page 5
```

and then searches for:

```text
iphone
```

There may not be enough iPhone products to have a Page 5.

If we keep the current page as 5, the API may return no products even though matching products are available on Page 1.

Therefore, whenever the search term changes, we reset:

```js
setCurrentPage(1);
```

This makes sure that the new search results always start from the first page.

It also gives a better user experience because the user can immediately see the first set of matching products.

## 4. How is the Pagination component used on two different pages?

The Pagination component is made reusable so that it can be used in different pages, such as the **Product/Home page** and the **Admin Orders page**.

The component can accept props such as:

```text
currentPage
totalPages
onPageChange
```

For example:

```jsx
<Pagination
    currentPage={currentPage}
    totalPages={totalPages}
    onPageChange={setCurrentPage}
/>
```

### What each prop does

**currentPage**
Tells the Pagination component which page is currently active.

**totalPages**
Tells the component how many pages are available.

**onPageChange**
A function passed from the parent component. It is called when the user clicks another page.

The parent component controls the actual page state:

```js
const [currentPage, setCurrentPage] = useState(1);
```

When the user clicks Page 2, the Pagination component calls:

```js
onPageChange(2);
```

The parent then updates:

```js
setCurrentPage(2);
```

The parent also uses the updated page number when requesting products or orders from the Flask API.

This makes the Pagination component reusable because the same component can work with different data and different pages. The child component displays the pagination UI, while the parent component controls which page is active and loads the corresponding data.

## Conclusion

In this task, SQL pagination is implemented using `LIMIT` and `OFFSET`. The `useDebounce` custom hook prevents unnecessary API calls while searching. Resetting `currentPage` to 1 ensures that new search results start from the first page. The reusable Pagination component accepts page-related props, while the parent component manages the active page and data fetching.
